# CARLA—MAGICIAN 离线视点库需求分析

## 1. 背景与目标

现有 `src.scout` 已能在 CARLA 中保存对齐的 RGB、米制深度和实例分割，`src.aod` 已验证
Town10HD_Opt 中的目标区域、车辆尺度和静态候选视点。MAGICIAN 的规划闭环需要的却不是一组互不关联的预览图，
而是一个具有相机内外参、合法移动边和可重复真实观测的局部环境。

第一阶段目标是构建一个小型、确定性、可验证的 **CARLA 离线视点库**，使 MAGICIAN 无需实时控制
CARLA，也能在同一局部区域完成闭环规划冒烟实验。该阶段回答工程问题：数据接口和规划闭环能否正确运行。
它不用于证明世界模型优于基线，也不直接训练目标检测器。

## 2. 系统边界

CARLA 仓库负责：

- 定义局部坐标系、候选视点和合法移动图；
- 在固定场景中采集同帧 RGB、深度、实例分割和真实相机位姿；
- 保存场景清单、节点、边、校验和与质量报告；
- 计算仅供评测使用的真实覆盖和动作后果。

MAGICIAN 仓库负责：

- 按已执行节点读取真实 RGB-D；
- 由历史真实观测更新场景表示；
- 用 Imagined Gaussians 评价候选视点，用束搜索规划；
- 只执行规划结果的第一步，再读取新观察并重新规划；
- 输出轨迹、预测增益和运行时间。

两个仓库通过版本化数据格式连接，不复制彼此的算法实现。CARLA 运行在 Linux 服务器；本机继续承担代码、
文档、离线测试和 Git 管理。

## 3. 功能需求

### R-01 场景可重复

一次采集批次必须固定地图、天气、时间、曝光、目标车辆、静态物体和动态 Actor 状态。所有节点属于同一个
世界快照，不能把分别生成不同车辆类别的 AOD 预览拼成一条轨迹。元数据必须记录 CARLA 版本、地图、
配置哈希、Git 提交和随机种子。

### R-02 位姿图生成

系统必须从一个配置文件生成有限节点和有向边。首个完整 Pilot 使用规则局部格点：

- 水平位置：中心周围 `3 × 3`；
- 高度：2 层；
- 偏航：4 个方向；
- 总候选数：`3 × 3 × 2 × 4 = 72`，几何拒绝节点仍保留状态记录；
- 边：相邻水平/垂直移动，以及同位置偏航 `±90°`。

格点间距、高度、偏航、俯仰和视场角必须可配置。72 只是首个 Pilot，不是算法假设。接口联调可以先采更小的
18 节点子集。

### R-03 节点与边合法性

相机中心不得位于膨胀后的静态障碍物包围盒内。移动边必须执行线段—障碍物相交检查，不能只检查端点。
系统必须区分 `inside_obstacle`、`segment_collision`、`outside_roi`、`capture_failed` 等原因。
静态 AABB 是第一阶段的近似碰撞模型；文档和结果不得把它描述成真实无人机可飞性证明。

### R-04 同帧多传感器采集

每个有效节点至少保存：

- RGB PNG；
- `float32` 米制深度 `N×M .npy`；
- 传感器有效掩码；
- 可选的原始实例分割 PNG，供诊断和评测使用；
- 相机内参、CARLA 位姿、局部位姿、frame、仿真时间戳和稳定性统计。

RGB、深度和实例分割必须具有相同 frame、尺寸和拍摄位姿。默认模型输入尺寸采用 456×256，水平 FOV
采用约 91.6°，以减少与 MAGICIAN/Macarons++ 输入分布的接口差异；如需同时保存高分辨率归档图，必须把两者
明确区分，不能在不同方法间使用不同相机参数。

### R-05 数据格式

每个视点库至少包含：

```text
viewbank/<scene_id>/
  scene.json
  nodes.jsonl
  edges.jsonl
  frames/<node_id>/
    rgb.png
    depth.npy
    mask.png
    camera.json
    instance.png        # 可选，算法输入默认不可见
  quality.json
  checksums.json
```

格式必须有 `schema_version`。路径均相对场景目录，复制到服务器或 MAGICIAN 仓库后仍可解析。

### R-06 规划时的信息隔离

虽然全部节点的图像预先存在磁盘，环境接口只能在策略执行到节点后返回该节点的 RGB-D。候选动作评分只能使用：

- 已访问节点的真实观测；
- 当前重建的场景表示；
- 位姿图中公开的合法边和动作代价；
- MAGICIAN 对未来覆盖的预测。

未访问节点的 RGB、深度、实例标签、真实覆盖增益和目标标签不得进入规划器。环境必须记录每次读取，检测越权访问。

### R-07 滚动规划

每个决策周期执行以下协议：读取当前真实观测，更新场景表示，生成合法候选，完成多步束搜索，只执行第一条边，
然后读取新节点的真实观测并重新规划。离线库只替换物理移动和传感器调用，不得把整条未来真实图像序列提前交给模型。

### R-08 坐标与深度转换

导出端必须保留原始 CARLA 坐标和变换矩阵；适配端必须显式转换 CARLA/Unreal 左手系与 PyTorch3D 相机约定。
CARLA 输出的沿射线距离 `d` 转换为相机 z-depth 时使用：

```text
z = d / sqrt(1 + ((u-cx)/fx)^2 + ((v-cy)/fy)^2)
```

转换必须通过投影—反投影误差测试和若干人工可解释点验证，不能仅凭渲染结果“看起来正确”。

### R-09 评测与基线

首个完整 Pilot 至少比较 Random、单步 Greedy 和 MAGICIAN Beam Search。评测包括：

- 最终表面覆盖率；
- 覆盖率—移动成本曲线下面积；
- 预测增益与真实增益的排序相关性；
- 首选动作相对真实最佳动作的 regret；
- 非法动作率、越权读取数和单步规划耗时。

Oracle 表面集合由所有有效节点的深度点云体素并集构造，只用于计算覆盖率和诊断，不得参与正常策略决策。

### R-10 校验与故障可诊断

采集结束必须生成机器可读质量报告，至少检查节点计数、重复 ID、引用完整性、文件哈希、图像尺寸、有限深度比例、
同帧对齐、请求/实际位姿误差、图连通性、孤立起点和中断恢复状态。失败批次保留已采数据和明确原因，但不得标记为完成。

## 4. 非功能需求

- **可复现**：同配置和种子产生相同节点、边和清单顺序。
- **可移植**：元数据使用 UTF-8、相对路径和明确单位；不依赖 Windows 盘符。
- **可测试**：格点、碰撞、坐标、深度、清单校验和环境访问控制均可在没有 CARLA 的本机测试。
- **可恢复**：采集支持断点续采；已通过哈希校验的节点不重复覆盖。
- **可审计**：训练/规划输入与诊断/Oracle 字段分开，避免标签泄漏。
- **性能边界**：第一阶段允许预采集，不要求无人机动力学实时性；单步规划耗时仍需记录。

## 5. 数据复用结论

`data/aod_preview_v2` 可复用其 Town10HD_Opt 区域坐标、目标尺度和人工选景结论，但不能直接作为视点库：它缺少
米制深度和合法移动边，而且不同类别由不同车辆实例分批生成。正式采集应使用新的输出目录和新的 schema，不覆盖旧数据。

## 6. 第一阶段验收门

满足以下条件才进入 MAGICIAN 适配：

1. 配置可离线生成确定性的节点图，起点所在有效子图连通且无意外孤立节点；
2. 小规模 CARLA 采集完成，所有成功节点的 RGB-D 同帧、位姿误差和深度有效率达到配置阈值；
3. 坐标转换的投影—反投影测试通过，点云方向、尺度和相机运动方向经人工核验；
4. 环境接口测试证明未访问节点不可读，Oracle 字段不进入规划器；
5. Random、Greedy 和 Beam Search 能在相同起点、预算和合法边上完成一轮可重复运行；
6. 输出能回答“模型预测了什么、实际获得了什么、为此移动了多远”，而不只展示好看的重建图。

## 7. 暂不纳入第一阶段

- CARLA 与 MAGICIAN 的实时 RPC；
- 真实无人机动力学、风场、控制器和连续轨迹优化；
- 大地图、多地图泛化和正式论文结论；
- detector、疑似目标记忆、漏检建模和 DINO-WM；
- 在线训练或微调 MAGICIAN。

这些功能建立在视点库闭环正确之后。第一阶段先验证 MAGICIAN 的几何建模与规划接口，避免同时调试采集、检测、
世界模型和飞控而无法定位错误。
