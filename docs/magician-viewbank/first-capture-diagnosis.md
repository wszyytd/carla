## 实际发现

- summary：请求 18，记录成功 17，几何拒绝 0，n_0003 因 sensor timestamp mismatch 失败。
- 有效节点图连通，起点 n_0008 有效且非孤立；清理失败为空。
- 所有 110 个已列文件的 SHA256 匹配，未发现传输损坏。
- 17 张 RGB 几乎全黑，0–255 尺度的全图均值约为 0.000006–0.001005，不能作为模型 RGB 输入。
  “亮度稳定”不代表曝光可用；旧稳定门接受了稳定黑帧，这是采集质量门的缺口。
- 元数据标为 ClearNoon，但实际太阳高度 0°，散射强度 0。旧代码没有比较请求天气与回读值。
  这与曝光问题相关，但仅凭离线文件不能断言是黑帧的唯一原因；UE5 渲染和手动曝光仍需实拍排查。
- 抽查 n_0000/n_0008/n_0017 深度是 float32、256×456、有限值比例 1，数值约 18.84–201.63 m。
  深度正常不代表 RGB 正常，也不代表已完成坐标和深度语义的点云验收。
- Windows 检查把 Linux 导出的局部旋转矩阵误报为不一致，差异仅约 1.11e-16，来自严格字典相等比较。

## 修复

1. 局部位姿重算使用有形状约束的数值比较，质量报告重算也使用绝对容差 1e-10。1e-3 的实际矩阵错误仍被测试拒绝。
2. 同帧 bundle 的短暂时间戳错配被丢弃并等待后续帧，稳定窗口重新建立；预算和原始阈值不变。
   保存拒绝次数及最后的帧号/时间戳证据，持续错配仍失败。
3. 使用显式版本化项目天气配置，读取实际天气并逐项比较；不再只相信 ClearNoon 名称。
   接口未生效时直接报告 weather readback mismatch，不继续生成貌似合格的数据。
4. 保存和离线检查均执行 RGB 均值质量门。新配置显式使用 5–250，旧配置读取使用相同默认且保留配置哈希。
5. 两份默认配置的 scene_id 改为 v2，服务器操作命令使用新输出目录，避免保留旧黑帧后只补拍失败点。

修复后的离线检查不再报 local pose mismatch，而是正确报告 17 个退化 RGB 和 1 个未采集节点。
天气属性参考 [CARLA UE5 Python API](https://carla-ue5.readthedocs.io/en/latest/python_api/#carlaweatherparameters)。
本项目显式天气值不是对所有 CARLA 内置预设的复刻；回读与真实画面必须同时验收。

## 2026-09-26：确认固定日间版本限制，纠正此前推断

doctor 返回 client/server=0.10.0、Town10HD_Opt、weather_enabled=false；连接已恢复。
[CARLA 0.10.0 官方发布说明](https://carla.org/2024/12/19/release-0.10.0/) 明确表示天气固定为日间，
不能修改云、雨、雾和太阳位置。因此此前让用户修复 WeatherClass/地图资源的结论缺乏依据，撤回该建议。
无天气 Actor 的占位回读不能反推出实际太阳高度，也不能解释黑帧原因。

默认配置改为显式 MapDefaultDaylight/v3：不调用天气 setter、不将占位值写成实际天气；
元数据标明参数不可观测、人工照明验收 pending。API 预设路径仍严格检查天气能力。
增加成功/黑帧、禁止天气写入、版本/能力限定、无伪造数值、同配置恢复测试。
曝光参数未盲目修改，黑帧门未降低；真实 v3 RGB 和深度验收仍待服务器运行。
