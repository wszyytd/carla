# S 形目标预见性主动观测实验设计

## 1. 实验定位

本实验是后续世界模型研究的前置诊断实验，编号为“实验 0”。它不训练目标检测器、
轨迹预测器或世界模型，也不处理建筑遮挡。实验只回答：

> 在无遮挡环境中，给定不同时长的目标未来轨迹信息，无人机能否在满足持续观测质量和
> 运动学约束的前提下，减少跟踪移动目标所需的飞行距离？

该实验用于测量“预测未来”的潜在收益上限，而不是把“切 S 形弯道比贴着目标飞更短”
作为研究结论。完整真实未来只作为 Oracle；后续学习模型必须在相同规划器和约束下替换
Oracle 输入，才能归因于预测能力。

当前 Town10 工程验收只使用一条连续、非路口的 120 m 弯道，累计转角至少 60°，用于验证
路线选择、目标执行和观测链路。这个单一弯道不足以支持正式研究结论；正式实验必须覆盖多个
路线形状和曲率等级，并在地图可用时包含 S/U 形路线。

## 2. 可证伪假设

- H1：完整未来 Oracle 在满足相同观测约束时，比只使用当前状态的反应式规划器飞行更短。
- H2：滚动规划可见的未来时域越长，路径长度总体越接近 Oracle，并最终趋于饱和。
- H3：目标路线越曲折，未来信息带来的路径节省越明显。
- H4：目标速度越高、观测约束越严格，允许切弯的空间越小，路径节省越少。
- H5：若悬停策略在多数场景中均满足约束，则当前场景或观测约束过松，实验无效。

下列任一结果都可以否定继续引入世界模型的必要性：

1. Oracle 相对反应式规划器没有稳定、实际可见的路径节省；
2. 路径节省仅在目标过小或明显偏离画面的情况下出现；
3. 悬停策略在全部难度条件下都满足观测约束；
4. 很短的匀速外推已经达到 Oracle，复杂预测模型没有剩余提升空间。

## 3. 实验变量

### 3.1 受控目标车辆

当前工程验收从 CARLA 地图 waypoint 中选择一条连续、非路口的 120 m 驾驶车道弯道，累计
转角至少 60°；不允许车辆脱离可驾驶区域。当前选择器只检查连续性、非路口、窗口长度和
累计转角，不检查建筑或视线。无遮挡是实验条件，必须通过人工路线验证确认所选路段没有建筑
遮挡视线。它只验证路线与观测工程链路，不能代表正式实验的路线分布。正式实验的目标路线应
覆盖多个形状和曲率等级，并在地图可用时纳入 S/U 形路线。

路线先表示为空间曲线，再按弧长重新采样，使车辆的参考速度在直道和弯道中一致。车辆由
轨迹跟踪控制器沿参考点运动，不能通过逐帧传送 Transform 伪造运动。每条路线必须检查：

- 车辆没有驶离车道；
- 目标速度误差在可接受范围内；
- 横向加速度不超过预设上限；
- 起点、终点和运行时长对所有策略完全相同。

每个策略回合不仅共享同一条参考路线，还必须核对车辆实际实现轨迹。若实际位置、速度或
到达时间相对参考轨迹超出配置容差，该回合记为目标执行失败，不进入策略比较。

正式实验使用多个路线形状、三个曲率等级和三个目标速度。具体路线坐标在服务器地图勘测后
写入独立配置，不在设计文档中硬编码。Town10 的单一 120 m 弯道仅是工程验收配置，不是
正式实验的第一轮样本。

### 3.2 无人机抽象

无人机在第一阶段表示为具有受限平移运动和受限云台转动的空中 RGB 相机。它不是瞬时移动
的自由相机，也不模拟完整旋翼空气动力学。

主实验固定飞行高度，暂定 40 m；相机暂定 1920×1080、水平 FOV 60°、10 Hz。仿真采用
固定 0.05 s 步长的同步模式。以下限制必须由配置提供并在每帧检查：

- 最大平移速度；
- 最大平移加速度；
- 最大 jerk；
- 云台俯仰和偏航范围；
- 云台最大角速度。

试运行可从 12 m/s 最大速度、4 m/s² 最大加速度和 90°/s 最大云台角速度开始，但这些是
工程初值，不应在没有灵敏度实验的情况下写成研究结论。

## 4. 观测约束

无遮挡不等于有效观测。每个仿真帧都根据 CARLA 真实三维包围盒、相机内外参和实例分割
真值计算目标观测质量。第一阶段不使用学习检测器，避免把感知误差混入规划验证。

一个时间步有效必须同时满足：

1. 目标三维包围盒投影位于图像范围内；
2. 投影框离图像边缘至少 5%；
3. 投影框短边不低于绝对像素阈值；
4. 目标中心归一化图像误差不超过阈值；
5. 目标与无人机距离不超过最大观测距离；
6. 实例分割中的可见目标像素数量不低于阈值；
7. 无人机和云台未违反任何运动学限制。

当前工程验收只生成一辆动态目标车，且不生成背景交通。因此实例像素数可在已投影目标框内，
从语义标签属于目标 Actor 的 `semantic_tags` 集合的像素中取出现最多的 `(G,B)` 实例颜色的
像素数，不写死不同 CARLA 版本可能改变的标签编号。CARLA 的实例颜色不能
与 Python `actor.id` 对应；这个启发式不是多车交通下的目标身份关联。加入背景交通或多个
动态车辆后，必须改用明确的实例—Actor 对应或单独的身份关联方法。

像素、中心误差和距离阈值先通过垂直跟随基线标定。建议同时保留一个绝对短边下限和一个
相对参考尺寸下限，避免仅按相对比例接受不可识别的小目标。正式值由标定结果写入配置。

主实验要求有效帧比例至少 99.5%，同时单独报告连续无效帧的最长时长。任何不满足门槛的
轨迹都记为失败，不能仅凭较短路径胜出。

## 5. 比较策略

所有策略从相同无人机初始状态开始，使用相同目标轨迹、相机配置、运动限制和观测约束。

### 5.1 Hover

无人机不平移，仅允许云台转向目标。它是退化诊断组，不是预期强基线。若它在大部分条件
中成功，说明路线空间范围或观测约束不足以要求主动移动。

### 5.2 Vertical Follow

无人机保持在目标车辆正上方，水平位置跟随目标，固定高度，云台向下观察。这是直观尾随
基线，也是路径长度和目标成像尺寸的标定参考。

### 5.3 Reactive Planner

规划器只读取当前目标真值状态，可使用匀速或匀加速短时外推，但不能读取真实未来路线。
它表示无需世界模型即可部署的传统方法。

### 5.4 Horizon Planner

规划器读取未来 H 秒目标真值轨迹，H 至少取 1、2、4 秒。除目标未来信息长度外，其优化器、
约束、初始化和迭代预算与 Reactive Planner 相同。

### 5.5 Full-route Oracle

规划器读取本回合完整目标真值轨迹，求解满足约束的近似最短无人机轨迹。它提供路径代价
下界和未来信息性能上限，不是可部署方法。

直线切弯可作为 Horizon/Oracle 的初始化轨迹或附加几何基线，但必须经过运动学和观测约束
检查，不能预先认定为最优。

## 6. 优化问题

规划器优化无人机位置序列 `p[0:T]` 和云台姿态序列 `g[0:T]`：

```text
minimize    sum_t ||p[t] - p[t-1]||_2

subject to  observation_quality[t] is valid
            speed[t] <= speed_max
            acceleration[t] <= acceleration_max
            jerk[t] <= jerk_max
            gimbal_angle[t] is within limits
            gimbal_rate[t] <= gimbal_rate_max
            altitude[t] == configured_altitude
```

第一版优先采用硬约束加单一主目标，不把全部指标混合成一个加权奖励。若优化器需要软约束
获得梯度，可以在内部使用罚项，但最终轨迹仍必须通过统一的硬约束验收。

完整路径优化和滚动时域规划必须共享同一个轨迹表示与约束检查器。滚动规划每次只执行第一
小段控制，然后读取新状态并重新规划。

## 7. 场景矩阵

正式实验至少覆盖：

| 因素 | 水平 |
| --- | --- |
| 路线形状与曲率 | 多个形状；低、中、高曲率；地图可用时含 S/U 形 |
| 目标速度 | 低、中、高 |
| 观测约束 | 宽松、中等、严格 |
| 未来时域 | 0、1、2、4 秒、完整未来 |

Town10 的单一连续弯道工程验收完成后，正式实验才在多个路线形状和曲率等级上打通并扩展
完整矩阵；单一路线结果不用于正式假设结论。

每个场景配置使用至少 5 个受控无人机初始偏移。所有策略在同一场景和初始偏移间配对比较。
若系统完全确定，随机重复不能代替场景变化；若加入控制噪声或状态噪声，则记录并复用种子。

## 8. 执行协议

1. 在同步模式下生成并验证一次目标参考轨迹。
2. 固定地图、天气、目标车型、目标轨迹和随机种子。
3. 每种策略独立运行一个回合，避免多相机同时渲染导致时间和负载不一致。
4. 每个回合先进行传感器预热，预热帧不进入正式统计。
5. 从统一起始帧开始记录，目标到达终点后统一结束。
6. 失败或超时也保留完整日志，不静默丢弃。
7. 所有轨迹结果写入按实验 ID 隔离的输出目录。

CARLA 世界设置必须在 `finally` 清理流程中恢复；脚本只销毁自己创建的 Actor，不能清理
其他客户端创建的车辆或传感器。

## 9. 输出和指标

### 9.1 主指标

- `episode_success`：有效帧比例及最长连续无效时间均通过门槛；
- `uav_path_length_m`：无人机三维轨迹长度；
- `path_length_ratio`：无人机路径长度除以目标路径长度；
- `saving_vs_reactive`：相对 Reactive Planner 的路径节省比例。

路径长度只在成功回合之间比较。失败率必须与成功回合路径长度并列报告。

### 9.2 观测指标

- 有效观测帧比例；
- 最长连续无效时间；
- 目标框短边的最小值、均值和分位数；
- 实例像素数量的最小值、均值和分位数；
- 目标中心归一化误差；
- 相机与目标距离。

### 9.3 运动和系统指标

- 最大/均值速度、加速度和 jerk；
- 最大/均值云台角速度；
- 违反每类约束的帧数；
- 每次规划耗时及其 P50、P95、最大值；
- CARLA 实际 FPS、丢帧数和传感器帧号连续性。

### 9.4 统计呈现

- 对同一路线、速度和初始偏移进行配对比较；
- 报告均值、中位数和 95% 置信区间；
- 先报告成功率，再报告成功轨迹的长度；
- 绘制路径长度与观测质量的 Pareto 图；
- 单独绘制未来时域 H 与路径节省的关系曲线。

## 10. 数据格式

每回合至少保存：

```text
out/path_cost/<experiment_id>/
├── config.resolved.yaml
├── episode.json
├── trajectory.csv
├── frame_metrics.csv
├── summary.json
├── preview.mp4
└── samples/
```

`trajectory.csv` 每帧包含目标和无人机的时间戳、位置、速度、加速度、云台姿态和规划器模式；
`frame_metrics.csv` 包含投影框、实例像素、中心误差、距离、有效标志及各约束违反标志。
原始高频 RGB/分割图像默认不全部保存，只保存诊断抽样帧和预览视频，避免无必要的数据膨胀。

## 11. 公平性和实现边界

- 各策略使用相同的目标真值和相机内参；
- Reactive 与各 Horizon Planner 使用相同在线求解器、每次重规划预算和终止条件；
- Full-route Oracle 允许使用更大的离线预算以逼近路径代价下界，其运行时间单独报告，
  不参与在线实时性比较；
- 第一阶段不使用检测器输出控制轨迹；
- 第一阶段不加入建筑遮挡、背景交通、身份重识别或世界模型；
- 第一阶段不把路径长度称为真实电池能耗；
- 真实未来、地图真值和实例分割真值必须在结果中明确标记为仿真特权信息。

## 12. 阶段验收

### 阶段 A：单场景工程验收

- 目标以近似恒速完成 Town10 连续、非路口的 120 m 弯道（累计转角至少 60°）；
- 五类策略均能运行并产生同格式日志；
- Hover 能暴露宽松约束下的退化情况；
- 所有路径长度由统一函数计算；
- 相机帧、世界帧和轨迹日志可对齐。

### 阶段 B：研究假设验收

- 至少完成多个路线形状和多个曲率等级，以及速度和观测约束的受控组合；
- 成功率和路径长度分开报告；
- 给出未来时域—路径节省曲线和 Pareto 图；
- 能明确接受或拒绝 H1 至 H5；
- 能依据 Oracle 与 Reactive 的差距判断是否值得进入目标未来预测或世界模型阶段。

## 13. 后续扩展顺序

若实验 0 证明未来信息存在稳定收益，再按以下顺序扩展：

1. 用匀速、匀加速、道路拓扑预测替换目标真值未来；
2. 用学习型目标轨迹预测器替换手工预测；
3. 在相同规划器中加入动作条件世界模型预测；
4. 最后再加入建筑遮挡、多出口路口和主动重捕获。

每一步只替换一个模块，保持场景、约束和指标不变，从而区分收益来自预测模型、规划器还是
更宽松的观测条件。
